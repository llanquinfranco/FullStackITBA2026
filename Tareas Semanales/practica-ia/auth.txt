B. Cuatro preguntas.
  1. ¿En qué archivo y en qué línea se hashea la contraseña? ¿Por qué no se guarda tal cual?
Se realiza en el archivo models/Usuario.js, dentro del middleware pre('save') utilizando la librería bcryptjs. No se almacena en texto plano por motivos de seguridad: en caso de una filtración o acceso no autorizado a la base de datos, las contraseñas no quedan expuestas, ya que el hash es una representación criptográfica unidireccional irreversible.

  2. ¿Qué viaja dentro del token? Decodifiquen uno (comando abajo) y péguenlo. ¿Por qué no puede ir la contraseña ahí?
Dentro del token viaja el payload que contiene el identificador único del usuario (id), su rol y las marcas de tiempo de emisión (iat) y expiración (exp). Ejemplo de un token decodificado:
{
  "id": "673f2a1b4c5d6e7f8a9b0c1d",
  "rol": "cliente",
  "iat": 1715690000,
  "exp": 1715693600
}
No puede incluirse la contraseña (ni siquiera en formato hasheado) porque el token se encuentra codificado en Base64url, un formato que puede ser decodificado fácilmente por cualquier usuario o herramienta externa, lo que comprometería la confidencialidad de los datos sensibles.

  3. ¿Por qué el login responde lo mismo si falla el email o si falla la contraseña?
Por motivos de seguridad, para prevenir ataques de enumeración de usuarios. Si el sistema diferenciara el mensaje de error según el motivo del fallo, un atacante podría deducir qué correos electrónicos se encuentran registrados en la plataforma y cuáles no. Al proporcionar una respuesta genérica e idéntica, se mitiga este vector de riesgo.

  4. ¿Por qué después de cambiar el rol a admin en Compass hay que volver a loguearse?
Porque el rol del usuario se encuentra firmado y almacenado dentro del payload del token JWT generado durante el proceso de inicio de sesión. Dado que el token ya fue emitido y firmado previamente, cualquier modificación directa realizada en la base de datos mediante MongoDB Compass no se refleja de forma automática en el token activo; por lo tanto, es necesario realizar un nuevo login para obtener un token actualizado con los nuevos permisos.
